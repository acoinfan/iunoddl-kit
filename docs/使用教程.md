# DDL 小本本使用教程

带插图的群聊示例见 [使用示例.pdf](使用示例.pdf)。下面的例子都按默认的通用模式（`mode: general`）写；作业模式只是叫法不同，见[两种模式](#两种模式)。机器人的名字默认是「尤诺」，可以在配置里改。

## 一分钟上手

1. **记一件事**：在已开放的群里发 `ddl 明天 报名决斗赛事`。或者先引用一条通知，再发 `ddl`。
2. **看草稿**：机器人回一张草稿卡片，标题是「📝 草稿 T1」，列出它整理出来的名称、截止时间、方式和说明。这时还**没有**写进看板。
3. **确认**：引用这张草稿卡片，回复 `ddl确认`，这件事就写进看板了。
4. **查看**：发 `ddl列表` 看所有没完成的事，发 `ddl#12` 看某一条的详情。

记错了，`ddl撤销` 能撤回自己上一次操作，24 小时内都有效。

## 引用卡片，就不用写编号

这是最重要的一条。机器人发的卡片分两种：

| 卡片 | 怎么认 | 编号 |
| --- | --- | --- |
| 草稿卡片 | 标题是「📝 草稿 T3」「✏️ 草稿 T3」之类 | `T` 开头，只在草稿阶段用，30 分钟过期 |
| 看板卡片 | 标题是「📌 事项 #12」，`ddl#12` 调出来的 | `#` 开头，就是看板上的编号，列表每行开头那个 |

**在手机上长按卡片 →「回复」，插件会从你引用的卡片里自己认出编号，你只管写要做什么。**只有不引用、插件没法从上下文知道你指哪一条的时候，才需要把编号写出来。

| 想做的事 | 引用草稿卡片回复 | 不引用时这样写 |
| --- | --- | --- |
| 确认写入 | `ddl确认` | `ddl确认T3` |
| 不要了 | `ddl取消` | `ddl取消T3` |
| 修改 | `ddl 截止周五晚上` | `ddl改T3 截止周五晚上` |
| 草稿里有几条，改第 1 条 | `ddl 第1条截止周五` | `ddl改T3 1截止周五` |
| 去掉第 2 条 | `ddl删2` | `ddl删T3 2` |
| 几条合成一条 | `ddl合并`（只合并其中几条：`ddl合并1 2`） | `ddl合并T3` |
| 再看一眼草稿 | `ddl` | `ddl草稿T3` |

| 想做的事 | 引用看板卡片回复 | 不引用时这样写 |
| --- | --- | --- |
| 修改 | `ddl 截止周五晚上`、`ddl 说明 黑海岸会派人支援` | 先 `ddl#12` 调出卡片，再引用它回复 |
| 删除 | `ddl删` | `ddl删#12` |
| 和别的条目合并 | `ddl合并#13`（把 #13 并进 #12） | `ddl合并#12#13` |

修改、删除、合并都会先出一份草稿给你看前后对比，还是要引用那份草稿回复 `ddl确认` 才真正写进看板；删除要回复 `ddl确认删除`。

另外几条规矩：

- 草稿只有发起人自己能确认、修改、取消，别人引用了也没用。手上的草稿发 `ddl草稿` 查看。
- 草稿 30 分钟没动会作废；机器人重启后草稿都会清空，但已经写进看板的不受影响。
- 引用卡片时发 `ddl列表`、`ddl草稿`、`ddl撤销` 这类指令，照常按全局处理，跟引用的是哪张卡片无关。
- 引用了看板卡片却回复 `ddl确认`，插件会提醒你要引用的是草稿卡片。

## 记一件事

三种写法都行：

- **直接打字**：`ddl 明天 报名决斗赛事`、`ddl 9/12 18:00 三王峰集合决战利维亚坦`。不引用时，这句话里**要有日期或「截止」之类的词**，插件才会当成一件事；`ddl 好多啊` 这种闲聊会被安静地忽略。
- **引用一条通知**：引用群里的通知或者转发进来的消息，发 `ddl`。`ddl` 后面还可以补一句说明，比如 `ddl 这是莫塔里商会的`。
- **引用合并转发的聊天记录**：同样发 `ddl`，插件会读整段记录。

一条通知里有几件事，草稿里就列几条。如果看板上已经有标题完全一样、还没完成的条目，草稿会提示「确认后会更新它」；想另建一条就引用草稿回复 `ddl 第1条新建`。

截止时间可以写 `10/18 23:59`、`10月18日`、`明天`、`今晚`、`下周五晚上8点`。只写日期的默认当天 23:59；写「24:00」算第二天 00:00。

解析靠 GSCore 里配置的 AI 模型，它只会提取原文里写了的信息，不会替你编分类或负责人。整理得不对，引用草稿直接改就行。

## 修改

可以写字段名，也可以直接说要怎么改：

| 字段名 | 改什么 |
| --- | --- |
| `标题`（也认「名字」「名称」） | 整个标题，原来的分类前缀不保留 |
| `事项名` | 只改名称，保留分类 |
| `分类` | 只改分类 |
| `截止` | 截止时间 |
| `方式`（也认「地点」「办理方式」） | 去哪儿、怎么交 |
| `说明`（也认「备注」「要求」） | 要带的材料、注意事项 |

例如 `ddl 截止 9/12 20:00 方式 三王峰集合`。不写字段名的，比如 `ddl 推迟两天`、`ddl 记得带邀请函`，交给模型理解，结果同样先出草稿给你核对。

## 合并、删除、撤销

- 同一件事被拆成了好几条：草稿阶段引用草稿回复 `ddl合并`；已经在看板上的用 `ddl合并#24#25`，后面可以跟新名字，比如 `ddl合并#24#25 商会事务`。合并会并进第一个编号，其余的删掉。
- 删除：引用看板卡片回复 `ddl删`，再引用删除草稿回复 `ddl确认删除`。
- 撤销：`ddl撤销` 撤回自己上一次通过 QQ 做的操作，24 小时内有效；`ddl撤销 #12` 撤回最近一次动过 #12 的操作，只有本人或管理员能撤。

## 直接问机器人

开了 GSCore 的 AI 功能的话，可以直接 @机器人：

- `@尤诺 最近有什么要办的？`
- `@尤诺 看看 #12 的截止时间。`
- `@尤诺 帮忙记一下：周六下午两点和达妮娅去观鸟。`

机器人能查看板、能帮你起草，但**不会替你确认、删除或撤销**，起草出来的草稿还是要你自己引用回复 `ddl确认`。

## 两种模式

| | 通用模式 `general` | 作业模式 `homework` |
| --- | --- | --- |
| 记什么 | 所有有截止时间、需要人去做的事：报名赛事、出征集合、商会账目、作业…… | 只记作业、实验、报告、测验，别的通知会被忽略 |
| 叫法 | 事项、分类、事项名、方式、说明 | 作业、课程、作业名、平台、要求 |
| 适合 | 大多数群 | 课程群 |

两种模式下写进看板的条目可以通用，随时可以切换。

## 配置在哪里改

配置文件是 GSCore 目录下的 `data/IunoDDL/config.json`。插件第一次加载时会生成它，里面的 `_说明` 一项逐条写了每个字段的意思。改完不用重启，下一条消息就生效；只有帮助图是 GSCore 缓存的，改了会影响帮助图的几项（下表标了「重启」）要重启 GSCore 才会重画。

| 想改什么 | 改哪里 | 说明 |
| --- | --- | --- |
| 看板的令牌、项目、视图、网址 | `vikunja_token`、`project_id`、`view_id`、`board_url` | 用 `deploy-site.sh` 部署的话，它会生成 `iunoddl-config.json`，再用 `install-plugin.sh --config` 填进来；手动部署时在 Vikunja 的「设置 → API 令牌」新建，权限见主 README |
| Vikunja 的地址 | `vikunja_api` | 和 GSCore 在同一台机器上就是 `http://127.0.0.1:3456/api/v1` |
| 在哪些群开放 | `allowed_groups` | 写群号，默认一个都不开；也可以 `install-plugin.sh --groups 群号1,群号2` |
| 记什么（模式） | `mode` | `general` 或 `homework`（重启）；也可以 `install-plugin.sh --mode` |
| 给模型的补充说明 | `extra_prompt` | 写这个群自己的说法，例如「老地方指埃弗拉德金库」「集合默认在三王峰」；留空就不加 |
| 机器人的名字 | `bot_name` | 默认「尤诺」（重启） |
| 帮助图的横幅 | 放一张图到 `data/IunoDDL/banner.jpg` | 插件自带的是 1545×300（重启） |
| 管理员、私聊 | `admins`、`private_users` | 管理员能撤销别人的操作、能私聊使用；GSCore 的主人和超级管理员本来就算 |
| 用哪个 AI 模型 | GSCore 自己的 AI 设置 | 插件不单独配模型和 API Key，用的是 GSCore 里配好的 |

`extra_prompt` 接在插件自己的规则后面，只用来帮模型理解群里的说法，改不了输出格式，也不会让模型执行通知里的指令。

## 常见问题

**发了 `ddl …` 没反应。**先看是不是在已开放的群里（`allowed_groups`）；再看那句话里有没有日期或「截止」之类的词，没有的话插件当成闲聊，不会回。

**回复「看板的钥匙还没配好」。**`vikunja_token`、`project_id`、`view_id` 有一项没填。

**回复「没找到有截止时间要办的事」。**模型觉得这段话里没有要做的事。写清楚一点，比如带上日期；也可以用 `extra_prompt` 告诉模型这个群的习惯说法。作业模式下，不是作业的通知都会这样回。

**引用了卡片，插件却说要写编号。**多半是引用的不是机器人的卡片，或者引用的是草稿以外的卡片做了确认。看看上面[引用卡片](#引用卡片就不用写编号)那两张表。
